rag-pipeline 1. Hybrid search (vector + BM25)

Search in Cynovela runs both vector search (based on semantic similarity) and BM25 (the classic keyword frequency based search algorithm), and merges the results; this"hybrid search" is the default. The implementation is inrag_retrieve() (an async function) atrag.py:1994.

1.1 Vector search

  • Model: BGE-M3 (a multilingual embedding model) by default. With--mode lite it is MiniLM-L12-v2, with--mode lite-en MiniLM-L3-v2, and with--mode minimal TF-IDF.
  • Store: ChromaDB. For each Collection ID it is split into the two stores{cid}__raw and{cid}__masked, and which one is queried is decided by the user role.
  • Diversity: MMR (Maximal Marginal Relevance) is enabled withmmr_enabled=true; a larger candidate set taken withmmr_fetch_k=20 is re-selected with the weightmmr_lambda=0.7 (rag.py:1654-1701).

rag-pipeline 1. BM25 search / merge methods (2/2)

1.2 BM25 search

  • Index: aBM25Okapi is kept in memory under the key(workspace_id, tier) (rag.py:101-107). It is built withbuild_bm25_index() when Publish completes, and rebuilt withrebuild_bm25_from_db() when needed.
  • Tokenization: Japanese uses fugashi (MeCab based), English is split on spaces. Both are consolidated inutils.tokenizer.tokenize().
  • Normalization: the score is normalized to [0, 1] before it is passed to the hybrid merge.

1.3 Hybrid merge methods

MethodFormula (conceptual)Default settings
rrf (default)score += 1.0/(rrf_k+vector_rank) + 1.0/(rrf_k+bm25_rank)rrf_k=60
weightedhybrid_score = vector_score*0.7 + bm25_score*0.3v=0.7bm=0.3

RRF (Reciprocal Rank Fusion) adds up the reciprocals of the ranks. Since it avoids adding together scores with different scales (cosine and BM25) directly, it is adopted as the default.

rag-pipeline 3. Differences between the 3 scores

ChunkHit (an individual search result) andRetrievalResult (the search as a whole) carry the following 3 scores (pipeline_types.py).

Score nameMeaningScaleUse
vector_scoreVector similarity (cosine)0 to 1Semantic similarity based on BGE-M3. Used for the confidence threshold decision
bm25_scoreBM25 normalized to [0,1]0 to 1Strength of the keyword match
rerank_scoreScore of the reranker re-evaluationProvider dependentFinal ranking of the top N. 0 means not applied

In addition,hybrid_score is computed as a provisional score after the hybrid merge, and when the reranker is not applied it decides the final ranking.

Design note: the decision for the low confidence fallback (abstention) is designed to usevector_score, not the RRF score. The RRF score (max ≈ 0.033) and the cosine similarity (0 to 1) differ by orders of magnitude, so confusing them breaks the threshold decision.

rag-pipeline 6. Confidence threshold (confidence_threshold)

This is the threshold used for the low confidence fallback (abstention: the behavior of withholding an answer and replying "I don't know" when the evidence is insufficient).

6.1 Setting (config.py:131-135)

# 低信頼度フォールバック: hits の最大 vector_score で判定
# BGE-M3 のノイズフロアは 0.35-0.45 (架空クエリでもこの程度の score が出る)
# 実存クエリは 0.55-0.75 程度のため 0.50 を境界に設定
"confidence_threshold": 0.50,

6.2 Why this value

  • BGE-M3 noise floor: 0.35 to 0.45 (even an unrelated query produces a score around this level)
  • Typical range for real queries: 0.55 to 0.75
  • Decision boundary: 0.50. Below this, the evidence is judged insufficient, and it becomes a candidate for withholding the answer or switching to general knowledge mode

rag-pipeline 6.3 An important note about scale (2/2)
The decision metric must bevector_score (cosine similarity, scale 0 to 1). It differs by orders of magnitude from the RRF score (the sum of reciprocal ranks, max ≈ 0.033), so making the threshold decision on the RRF score makesabstention fire on every query. Interpret the value ofconfig.rag.confidence_threshold on the assumption of the cosine scale.

This is a lesson from a fatal bug that actually happened in Cynovela in the past. It was solved at the root by changing the abstention decision metric from RRF to vector cosine.

rag-pipeline 1. ハイブリッド検索（ベクター + BM25）

Cynovela の検索は、ベクター検索（意味的類似度ベース）と BM25（古典的なキーワード頻度ベースの検索アルゴリズム）の両方を実行し、その結果を統合する「ハイブリッド検索」を既定としています。実装はrag.py:1994 のrag_retrieve()（非同期関数）にあります。

1.1 ベクター検索

  • モデル: 既定では BGE-M3（多言語埋め込みモデル）。--mode lite では MiniLM-L12-v2、--mode lite-en では MiniLM-L3-v2、--mode minimal では TF-IDF。
  • 保管庫: ChromaDB。Collection ID ごとに{cid}__raw と{cid}__masked の 2 つに分かれ、利用者ロールに応じて引き先が決まります。
  • 多様性確保: MMR（Maximal Marginal Relevance）がmmr_enabled=true で有効、mmr_fetch_k=20 で多めに取った候補からmmr_lambda=0.7 の重みで再選別（rag.py:1654-1701）。
Cynovela 非公式・個人学習目的
rag-pipeline 1. BM25 検索 / 統合方式 (2/2)

1.2 BM25 検索

  • インデックス: メモリ上にBM25Okapi を(workspace_id, tier) キーで保持（rag.py:101-107）。Publish 完了時にbuild_bm25_index() で構築、必要時にrebuild_bm25_from_db() で再構築。
  • トークン化: 日本語は fugashi（MeCab ベース）、英語はスペース区切り。utils.tokenizer.tokenize() に集約。
  • 正規化: スコアは [0, 1] に正規化されてからハイブリッド統合に渡されます。

1.3 ハイブリッド統合方式

方式計算式（概念）設定値の既定
rrf（既定）score += 1.0/(rrf_k+vector_rank) + 1.0/(rrf_k+bm25_rank)rrf_k=60
weightedhybrid_score = vector_score*0.7 + bm25_score*0.3v=0.7bm=0.3

RRF（相互順位融合）は順位の逆数を足し合わせる方式で、スケールの違うスコア（cosine と BM25）を直接合算しないで済むため、既定として採用されています。

rag-pipeline 3. スコア 3 種の違い

ChunkHit（個々の検索結果）とRetrievalResult（検索全体）は次の 3 種のスコアを持ちます（pipeline_types.py）。

スコア名意味スケール用途
vector_scoreベクター類似度（cosine）0〜1BGE-M3 ベースの意味的類似度。信頼度閾値判定に使用
bm25_scoreBM25 を [0,1] 正規化0〜1キーワード一致の強さ
rerank_scoreReranker 再評価スコアProvider 依存上位 N 件の最終順位。0 なら未適用

加えて、ハイブリッド統合後の暫定スコアとしてhybrid_score が計算され、Reranker 未適用時はこれが最終順位を決めます。

設計上の注意: 低信頼度フォールバック（Abstention）の判定には RRF スコアではなくvector_score を使う設計です。RRF スコア（最大 ≈ 0.033）と cosine 類似度（0〜1）は桁が違うため、混同するとしきい値判定が壊れます。

rag-pipeline 6. 信頼度閾値（confidence_threshold）

低信頼度フォールバック（Abstention：根拠不足のときに回答を保留・「分かりません」と返す挙動）の判定に使うしきい値です。

6.1 設定値（config.py:131-135）

# 低信頼度フォールバック: hits の最大 vector_score で判定
# BGE-M3 のノイズフロアは 0.35-0.45 (架空クエリでもこの程度の score が出る)
# 実存クエリは 0.55-0.75 程度のため 0.50 を境界に設定
"confidence_threshold": 0.50,

6.2 値の根拠

  • BGE-M3 ノイズフロア: 0.35〜0.45（無関係なクエリでもこの程度の score が出る）
  • 実存クエリの典型範囲: 0.55〜0.75
  • 判定境界: 0.50。これを下回ると「根拠不足」と判断し、回答保留や一般知識モードへの切替候補となる
Cynovela 非公式・個人学習目的
rag-pipeline 6.3 スケールに関する重要な注意 (2/2)
判定指標は必ずvector_score（cosine 類似度・0〜1 スケール）を使います。RRF スコア（順位の逆数和、最大 ≈ 0.033）と桁が違うため、RRF スコアでしきい値判定を行うと全クエリで Abstention が暴発します。config.rag.confidence_threshold の値は cosine スケール前提で解釈してください。

これは過去に Cynovela で実際に発生した致命的バグの教訓です。Abstention 判定指標を RRF から Vector cosine に変更することで根本解決しました。
