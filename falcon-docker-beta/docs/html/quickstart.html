Quick Start About This Document
About This Document
Cynovela is a completely unofficial learning tool, built so that one individual can understand the concepts of an AI platform tool by working on them hands-on. It is not a commercial product or an official implementation. Everything is implemented originally, on an OSS stack of FastAPI / SQLite / ChromaDB / BGE-M3 / a local LLM. It does not represent the official view of any company or product in any way.

This document shows the shortest procedure from starting Cynovela for the first time to asking your first RAG (Retrieval-Augmented Generation) question.

Quick Start 2. Setting Up the conda Environment

Cynovela has been verified on a conda environment. Create the environment with the following procedure.

# conda 環境を作成（任意の名前。例: cynovela）
conda create -n cynovela python=3.11 -y

# 依存ライブラリをインストール

Quick Start 3. First Model Download (by Mode)

At startup Cynovela runs a model existence check called the "Preflight check". The required Embedding (the model that turns text into vectors) differs depending on the startup mode (--mode).

Model Size by Mode

ModeRequired modelApproximate size
text (default)BAAI/bge-m3about 2.3GB
liteSwitching is not wired up, so BAAI/bge-m3 is what is actually used (the behavior is the same as text; only the display name changes)—
lite-enSwitching is not wired up, so BAAI/bge-m3 is what is actually used (the behavior is the same as text; only the display name changes)—
Important: If you choose a mode of text or above on the first start, a download of about 2.3GB occurs. Depending on the network it can take from several minutes to more than ten minutes.

When using a real LLM, start LM Studio at http://localhost:1234 and then run the following command.

Quick Start 5. Logging In with a Demo Account

Open http://127.0.0.1:8765 in a browser. When started with --demo, demo users are seeded automatically.

The roles the DB holds are the two values admin / viewer.

RolePermissions
adminAll features. Full permissions, including user management, system settings, and viewing the PII detection history
viewerViewing only. RAG search and report viewing
Names such as curator / data-scientist are normalized internally to viewer.

The actual login information of the shipped demo.db:

User nameRolePassword
cynovelaadminA change is forced at the first login (no fixed password is distributed)
demoviewerSee viewer_password in the bundled credential file (the *.admin-password.txt received separately from the package tar). No fixed password is distributed

After logging in, the screens that are shown and the range of operations available change according to the role.

Quick Start 6. Creating Your First Workspace

A "Workspace" is the management unit that groups users, policies, and collections together. In a --demo start, only one workspace, containing the bundled dummy documents, is present (the three empty seed workspaces were removed on 2026-07-30 and are stripped out at startup). Three guardrail policies are seeded, so assign them to the workspace you create and use them.

To create a new workspace, you can create it from the "Workspace Management" screen of the GUI. The detailed procedure is shown in "Hands-on (Basics)" described later.

Cynovela Unofficial / personal learning / Alpha GA
Quick Start 7. Ingesting Your First File

Create a "Collection" under the workspace and ingest the target files into it. A collection is the unit of a set of files and a chunking strategy, and it has the state transitions draft → ingested → ready.

On the GUI, operate in the following order.

  1. Select a workspace
  2. Press the "Create Collection" button and specify a name and a RAG strategy (simple / hybrid_bm25 / contextual)
  3. Upload the files (drag and drop is supported)
  4. Run "Publish" to bring it to the ready state
Cynovela Unofficial / personal learning / Alpha GA
Quick Start 7. What Publish Does (2/2)

The following are performed during Publish.

  • Text extraction (PDF / DOCX / image OCR and others)
  • Chunking (500 characters by default, with 50 characters of overlap)
  • PII detection and masking (ingest-time masking)
  • Embedding generation and storage into ChromaDB
  • BM25 index build
Note: Publish runs in the background and returns progress over SSE (Server-Sent Events). On completion, the number of items and the elapsed time are recorded in the publish_history table.

Quick Start 8. Your First Question

Against a collection in the ready state, ask a question from the "RAG Chat" screen of the GUI.

For example, ask it like this.

このドキュメントで扱われている主なトピックは何ですか？

Together with the answer, the chunks are shown as citations with reference numbers such as [1][2] (when config.rag.citation_enabled = true).

You can also experience the difference made by the role.

  • When logged in as admin: searches the raw text store. No masking is applied to the output either.
  • When logged in as viewer: searches the masked text store. Exit masking is also applied to the LLM output, and PII (Personally Identifiable Information) is replaced by masking (curator / data-scientist and so on are normalized to viewer).

クイックスタート 7. Publish で行われる処理 (2/2)

Publish の過程で以下が行われます。

  • テキスト抽出（PDF / DOCX / 画像 OCR ほか）
  • チャンク分割（既定 500 文字、オーバーラップ 50 文字）
  • PII 検出とマスキング（取込時マスキング）
  • Embedding 生成と ChromaDB への保存
  • BM25 インデックス構築
補足: Publish はバックグラウンドで動き、SSE（Server-Sent Events）で進捗を返します。完了時には publish_history テーブルに件数や所要時間が記録されます。

クイックスタート 8. 最初の質問

ready 状態のコレクションに対して、GUI 上の「RAG Chat」画面から質問を投げます。

たとえば次のように尋ねます。

このドキュメントで扱われている主なトピックは何ですか？

回答とともに、出典として [1][2] のような引用番号付きでチャンクが表示されます（config.rag.citation_enabled = true の場合）。

ロールによる違いも体験できます。

  • admin ログイン時: 生本文（raw）保管庫を検索。出力にもマスクは入りません。
  • viewer ログイン時: マスク済み本文（masked）保管庫を検索。LLM 出力にも出口マスクが適用され、PII（Personally Identifiable Information：個人情報）はマスキングに置換されます（curator / data-scientist 等は viewer に正規化）。
