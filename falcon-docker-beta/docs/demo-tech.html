コンポーネント構成

FastAPI を中心に、Provider 抽象化（LLM / Embedding / Reranker / VectorStore / Classifier）と Guardrail / RAG / 監査の各レイヤを組み合わせる構成です。

判定ロジック: 重要コンポーネント（FastAPI Server / Guardrail）は警告色で強調しています。Provider 配線は _wire_providers_for_mode() が yaml.reranker.provider → legacy の優先順で行います（--mock は撤去済み）。

RAG パイプラインフロー

クエリ受信から回答返却までの 7 段階を可視化します。Hybrid 統合は RRF（k=60）で順位融合します。

補足: Adaptive RAG（complexity score ≥ 2.0）が起動すると Agentic ループに入り、CRAG / Multi-Query / HyDE を活用して最大 3 回の反復検索が行われます。Abstention 判定は RRF ではなく Vector cosine スコア（しきい値 0.50）で行います。
Alpha GA 既知制限: 構造化回答テンプレートは未実装で、自由形式回答が標準です。低信頼度フォールバック（threshold=0.50）は設定済みですが、検索 0 件時の自動切替は完全には統合されていません。

Dual-Tier 保管設計

同じ文書を「raw（生本文・Fernet 暗号化）」と「masked（マスク済）」の 2 系統に分離して保管します。Publish 時に _mtws_publish = guardrail.mask_text_with_spans が両 tier を生成します。

判定ロジック: tier_for_role(role) が role == 'admin' なら 'raw' を、それ以外なら 'masked' を返し、対応する保管庫へルーティングします。vault_enc.enc_raw / dec_raw が enc: プレフィックス付きの冪等なインターフェースを提供します。

RBAC ロール別 権限表

DB 制約: role TEXT NOT NULL CHECK(role IN ('admin', 'curator', 'viewer'))。計 3 種です。

ロール保管庫 tier出口マスク主な権限
admin raw 素通し 全 API / users / policies / audit_logs / settings / pii-detections
curator masked 強制マスク コレクション編集 / ソース追加 / publish
viewer masked 強制マスク RAG 検索 / 閲覧のみ

プロンプトインジェクション 3 層防御

routers/chat.py の 3 層パイプラインで、入力・取得・出力の各段階を検査します。検出時は audit_logs に PROMPT_INJECTION_BLOCKED を記録します。

層関数動作
入力検査 detect_prompt_injection 14 種の英日パターンを検出 → HTTP 400 で遮断
Retrieval 後検査 filter_poisoned_chunks context 構築前に該当チャンクを除外
出力検査 detect_output_exfiltration LLM 応答中の HACKED / PWNED / SECRET-ALPHA-TOKEN / [SYSTEM OVERRIDE] を検知
Alpha GA 既知制限: 間接プロンプトインジェクション（取り込んだ文書内に仕込まれた指示）の完全検出は Phase 3 で対応予定です。現状は filter_poisoned_chunks のパターンマッチに依存しています。
