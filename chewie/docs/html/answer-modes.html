About this document
Cynovela is a completely unofficial learning tool, built by an individual in order to understand the concepts behind AI platform tooling by actually writing the code. It is not a commercial product and not an official implementation. Everything is implemented from scratch on an OSS stack of FastAPI / SQLite / ChromaDB / BGE-M3 / a local LLM. It does not represent the official position of any company or product.

The behavior of a Cynovela RAG (retrieval augmented generation) answer changes with the combination of amode and apreset, depending on the use case. This document organizes the modes that can be confirmed as of , together with the implementation evidence.

Answer Modes 1. Strictness modes (2 kinds)

Two system prompts are defined inrag.py. This is the switching axis that corresponds to the "strictness mode".

1.1 DEFAULT_SYSTEM_PROMPT (default / RAG enabled)

  • Instructs the model to answer based on the ingested documents (the context)
  • Recommends embedding the citation numbers[1][2]

1.3 Switching

  • Default:DEFAULT_SYSTEM_PROMPT (RAG enabled, answer based on the search results)
  • General knowledge mode:GENERAL_KNOWLEDGE_SYSTEM_PROMPT (RAG disabled, answer from the general knowledge of the LLM only)

From MCP (external tools), calling therag_general tool requests a direct answer without RAG.

Answer Modes 4.1-4.2 Confidence threshold

4.1 Setting (default)

# config.py の defaults
rag:
  confidence_threshold: 0.50
  • Scale: cosine similarity (0 to 1)
  • Noise floor of BGE-M3: 0.35 to 0.45 (even an unrelated query produces a score around this level)
  • Typical range for real queries: 0.55 to 0.75
  • Decision policy: 0.50 or below is treated as "low quality" and becomes a fallback candidate

4.2 The decision metric is the vector cosine

As a lesson from the past,using the RRF score for the abstention (answer suppression) decision is wrong. RRF is the sum of reciprocal ranks (max ≈ 0.033), which differs by orders of magnitude from the cosine similarity (0 to 1). Always use thevector cosine as the decision metric.

Answer Modes 4.3-4.4 Integration status / tuning policy

4.3 Integration into the pipeline

config.rag.confidence_threshold is defined as a value, but inside the search pipeline (rag_retrieve) it is onlypartially integrated into explicit exclusion logic.

  • Handling of 0 search results → automatic switching toGENERAL_KNOWLEDGE_SYSTEM_PROMPT is not implemented
  • A separate processing flow for a top score < threshold is not implemented

4.4 Tuning policy

The threshold can be changed by editingrag.confidence_threshold incynovela.yaml. Hard-coding is forbidden; it is only changed through the configuration file.

回答モード 4.1〜4.2 信頼度閾値

4.1 設定値（既定）

# config.py の defaults
rag:
  confidence_threshold: 0.50
  • スケール: コサイン類似度（0〜1）
  • BGE-M3 のノイズフロア: 0.35〜0.45（無関係なクエリでもこの程度のスコアが出る）
  • 実存クエリの典型範囲: 0.55〜0.75
  • 判定方針: 0.50 以下を「低品質」とみなすフォールバック候補

4.2 判定指標は vector cosine

過去の教訓として、Abstention（回答抑制）判定に RRF スコアを使うのは誤り です。RRF は順位の逆数和（最大 ≈ 0.033）であり、コサイン類似度（0〜1）と桁が違います。判定指標は必ずvector cosine を使ってください。

回答モード 4.3〜4.4 統合状況 / 調整方針

4.3 パイプライン統合状況

config.rag.confidence_threshold は値としては定義済みですが、検索パイプライン（rag_retrieve）の中で明示的な除外ロジックには部分統合 に留まります。

  • 検索結果の 0 件処理 →GENERAL_KNOWLEDGE_SYSTEM_PROMPT への自動切替は未実装
  • 最高スコア < threshold での別処理フローは未実装

4.4 調整の方針

cynovela.yaml のrag.confidence_threshold を編集することで閾値を変えられます。ハードコードは禁止されており、設定ファイル経由のみで変更します。
