About this document
Cynovela is a completely unofficial learning tool, built so that an individual can understand the concepts of an AI platform tool by working on it hands-on. It is not a commercial product and not an official implementation. The implementation is entirely original, and is composed of an OSS stack of FastAPI / SQLite / ChromaDB / BGE-M3 / a local LLM. It does not represent the official position of any company or product in any way.

README 1. Project Overview

It is designed to experience "what it is like to actually build it" for the following kinds of features provided by the AI platform tool it was inspired by.

  • Data governance (guardrails, PII detection, audit logs)
  • Data ingest (automatic classification, metadata extraction, differential sync)
  • RAG (Retrieval-Augmented Generation) pipeline (hybrid search, Reranker, Multi-Query, CRAG, HyDE)
  • Role-Based Access Control (RBAC)
  • MCP (Model Context Protocol) integration

The implementation is entirely original and contains no source code from the tool it was inspired by. It is built only from OSS.

README 2. Main Features

2-1. Data ingest (Smart Ingestion)

  • Automatic classification into 14 document categories (governance policy, incident report, technical guide, meeting minutes, audit report, and so on)
  • 3 classification engines (lightweight rule-based, local LLM, hybrid)
  • Automatic tracking of sources by hash-based differential sync

2-2. Guardrails and PII detection

  • Detection of 8 PII (personal information) patterns (email, phone, credit card, My Number, IP address, and so on)
  • Exit masking through dual-tier storage (raw / masked)
  • Protection of raw text by Fernet encryption
  • Three layers of prompt injection countermeasures

README 2. Main Features (continued) (2/2)

2-3. RAG pipeline

  • Hybrid integration of BM25 + vector search (RRF or weighting)
  • Vector embedding by BAAI/bge-m3
  • Reranker (supports several, such as CrossEncoder, FlashRank, and Ollama)
  • Advanced search features including Multi-Query, CRAG, HyDE, MMR, and Parent-Child chunking
  • Answer style per role (admin / reader)

2-4. RBAC and auditing

  • 3 roles (admin / curator / viewer)
  • Recording of important operations into the audit_logs table
  • Tampering with audit logs through the API is prohibited

2-5. External integration

  • LM Studio / Ollama / OpenAI-compatible API connection
  • MCP server (11 tools)
  • LAN sharing and Tailscale sharing

README 4. Quick Start

4-1. Recommended environment

  • macOS (Apple Silicon recommended), Linux, Windows
  • Python 3.10 or later
  • conda environment (recommended environment name: cynovela)

4-2. Starting in demo mode

python server.py --demo
  • --demo: starts with demo data loaded (reset on restart)

Opening http://127.0.0.1:8765 in a browser shows the UI.

README 4-3. Real LLM Mode and 4-4. Startup Modes

Start LM Studio, enable its OpenAI-compatible API, and then run the following.

python server.py --demo --lmstudio-url http://localhost:1234

--mode accepts text / lite / lite-en (the switching is not wired up; only the displayed name changes).

modePurposeRequired model
textAll text RAG features (default)BAAI/bge-m3
liteSwitching is not wired up = actually BAAI/bge-m3 (behavior is the same as text; only the displayed name changes)—
lite-enSwitching is not wired up = actually BAAI/bge-m3 (behavior is the same as text; only the displayed name changes)—
