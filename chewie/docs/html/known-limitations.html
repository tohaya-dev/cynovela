About this document
Cynovela is a completely unofficial learning tool, built so that an individual can understand the concepts of an AI platform tool by working on it hands-on. It is not a commercial product and not an official implementation. The implementation is entirely original, and is composed of an OSS stack of FastAPI / SQLite / ChromaDB / BGE-M3 / a local LLM. It does not represent the official position of any company or product in any way.

This document describes what Cynovelacannot do. Explanations of what it can do are inREADME.md andquickstart.md. Here we write only the things that will disappoint you if you expect them.

The version is1.0.2 (APP_VERSION incore/version.py is the single source, andGET /api/health and/docs read it from there).

WHAT THIS TOOL CANNOT DO 1. What Masking Cannot Do (1/7)

This is the heaviest section. Masking is a "mechanism to hide personal information," but the range it can hide has a clear limit.The fact that masking was applied does not mean all personal information in the material has disappeared. Things that cannot be hidden always remain.

1.1 The rules can only catch the 13 types that have a fixed form

The types written inPII_PATTERNS ofguardrail.py are only the following 13.

TypeWhat it meansTypeWhat it means
URLAn address starting with http / httpsPASSWORDA labeled value such as "password: XX"
EMAILEmail addressAPIKEYAPI key or access token
PHONE_JPMobile phone number (070 / 080 / 090)PRIVATEKEYPrivate key block
PHONE_LANDLandline phone numberSSNUS Social Security Number (3-2-4 form)
CREDITCredit card numberIBANInternational Bank Account Number
MYNUMBERMy Number (Japanese individual number)PASSPORTPassport number (2 letters + 7 digits)
IPV4IPv4 address

Nothing else is masked by the rules, not even once. For example, employee numbers, customer numbers, contract numbers, bank account numbers (other than IBAN), vehicle numbers, and insurance card numbers are out of scope.

The rules match on "form." If the form is broken, they do not match. Conversely, unrelated numbers that happen to match the form are masked.

WHAT THIS TOOL CANNOT DO 1.2 / 1.3 Names, Addresses, Organization Names, Place Names (2/7)

1.2 Names and addresses are left to language analysis; withlite they are not masked at all

Names and addresses are not among the 13 types above. Their form is not fixed, so the rules cannot catch them, and they are handled on the language analysis (NER) side.

  • The setting ispii_mode incynovela.yaml. The default isstandard.
  • Only when it isstandard doPERSON_JP (name) andADDRESS_JP (address) work.
  • If you setpii_mode tolite, neither names nor addresses are masked at all.lite switches to a path that judges only with regular expressions, and the recognizers for names and addresses are not assembled in the first place (get_active_recognizers() anddetect_pii() inutils/metadata/pii.py).

Name detection only matches words registered as family or given names. Rare names, katakana transcriptions of foreign names, nicknames, and writing that is fused with a job title are missed. For addresses as well, it only looks at writing that starts with a prefecture and at the postal code form, so writing such as "3rd floor of the head office building" or "XX branch" is not treated as an address.

1.3 Organization names and place names exist only as names, with no substance

get_active_recognizers() also returnsORG_JP (organization name) andLOC_JP (place name). The names are returned, butnot a single recognizer that supplies them is registered (in the whole tree, these two words appear only on that one line).

In other words, neither organization names nor place names are masked. Do not assume they are working just because their names appear in the list.

WHAT THIS TOOL CANNOT DO 1.4 / 1.5 Regression, and the Conditions Where Values Get Cut (3/7)

1.4 Without a language model, it falls back to rules only even instandard

Detecting names and addresses requires the spaCy / GiNZA language model. In an environment where this is not installed, detection falls back to regular expressions only, even whenpii_mode is stillstandard. At startup,launch.sh checks whether it exists and, if not, prints the following warning.

⚠️  spaCy モデル '...' が未導入です (standard PII が regex フォールバックします)。'pip install -r requirements.txt' を実行してください。

While this warning is shown, neither names nor addresses are being masked. Startup does not stop, so if you skip over the warning you will keep using the tool while believing that masking is in effect.

1.5 Passwords and API keys get cut at spaces, Japanese characters, and line breaks

The rules forPASSWORD andAPIKEY pick up the value part only as ASCII graphic characters (guardrail.py states explicitly that the value is ASCII graphic characters[!-~] only, and always gets cut at a space or a CJK character). For this reason, the following cannot be caught.

  • Values with a space inside them (パスワード: abc def) → they are cut afterabc
  • Values with Japanese characters inside them
  • Values that span line breaks (the whitespace between the label and the value is limited to tabs and spaces, and does not span line breaks)

Also, anything without a separator (:：=＝ or the Japanese particle "は") between the label and the value is out of scope. This design avoids catching common words such aspassword protection, and the price of it is that a space-separated form such as "パスワード　abcdefgh" cannot be caught.

WHAT THIS TOOL CANNOT DO 1.6 Spaces in PDFs Escape Masking (4/7)

A PDF is composed not as a sequence of characters but as information about where to place characters. When characters are extracted from it, spaces that were not in the original appearance may be inserted in the middle of words.

The masking rules look at the sequence of characters, so a single inserted space is enough to make them not match. For an email address it looks like the following.

Extracted stringResult
taro.yamada@example.co.jpMasked
taro.yamada @example.co.jpNot masked (cut before the@)
taro.yamada@ example.co.jpNot masked (cut after the@)
taro. yamada@example.co.jpOnly theyamada@example.co.jp part is masked, andtaro. remains

The same thing can happen for other types as well, such as phone numbers and card numbers.When you ingest a PDF, check with your own eyes whether masking has been applied. You can see the actual text from the chunk list after the ingest.

WHAT THIS TOOL CANNOT DO 1.7 Conditions Under Which the Administrator Can See the Original Text (5/7)

When the role isadmin, the design lets you see the original text before masking (tier_for_role inrag.py). However, in the following 3 cases even the administrator gets only the masked version.

  1. When the destination of the answering LLM points outside._effective_send_tier inrouters/chat.py drops to the masked version regardless of role when the destination is neither inside the local machine, nor the host side of a container, nor a private address range. It also falls back to the masked version when the destination cannot be determined.
  2. When the key of the vault (encrypted storage) does not match. The original text is stored encrypted, and_vault_substitute_raw inrag.py decrypts it. Rows that cannot be decrypted use the masked text as it is (this is done deliberately so that ciphertext is not shown on the screen). If you replace the key after receiving the package, even the administrator can no longer read the original text of material ingested before that.
  3. The question text itself. Masking of the question text is not divided by role. Even if the administrator writes an IP address in the question, that IP is masked before being passed to the search and to the LLM.

An earlier version of this document said "the IP is masked even for the administrator (under investigation)," and the 3 items above are the reason. It is not a defect.

WHAT THIS TOOL CANNOT DO 5. Conditions Under Which External Transmission Stops

Rather than "what it cannot do," this is "what is deliberately stopped." When it cannot decide, it always falls to the stopping side. To that extent, features may look as if they are not working.

  • The CRAG preview. The processing that has the LLM pre-read whether the search results are sufficient for the question is not executed when the destination is not inside the local machine, orwhen the destination cannot be determined (rag.py). When it is not executed, it falls back to "adopt the search results as they are." The screen shows[CRAG] 非ローカル宛のため下読みをスキップします.
  • Conversation summarization and extraction of clues from answers. Both use the same decision, and for external destinations (including the undeterminable case) they return empty without sending (routers/chat.py).
  • Sending original text based on role. If the destination is external, only the masked version is sent, even for the administrator (_effective_send_tier).
  • If masking fails, it stops. For both the question text and the answer, if the masking process fails with an exception it returns 503 and aborts the processing. It does not return the version before masking instead (routers/chat.py).
  • The combination of ingest without masking and external embedding is rejected. Collections created in an old version "without masking" cannot be published while external embedding is enabled (rag.py).

WHAT THIS TOOL CANNOT DO 6. Constraints When Used Concurrently
  • Publish is limited to 2 at the same time. The 3rd one waits 5 seconds and, if no slot opens, is returned as a failure (server.py; the screen shows "他のPublishが多すぎます。少し待ってから再試行してください。").
  • Concurrent LLM execution is limited to 3 by default (llm.max_concurrent incynovela.yaml;server.py creates a semaphore with this value). The 4th one waits until a previous call finishes.
  • Storage is a single SQLite file (WAL mode). In situations where writes overlap, waiting occurs. Usage where dozens of people run ingests at the same time is not assumed.
  • The vector index (ChromaDB) is also a file on the same machine. Do not rewrite the same index from multiple processes.

WHAT THIS TOOL CANNOT DO 10.2 Cross-Collection Search / MCP / How Answers Are Built

Cross-collection search

The MCP tools includesearch_across_collections (search across multiple collections), butthe screen (GUI) has no entry point for cross-collection search. From the screen you select one workspace and search.

MCP

  • mcp_server.py provides 11 tools.
  • The MCP server is built to query the Cynovela REST API internally with authentication. In other words,if the main application is not running, MCP does not run either.
  • The Python executable that runs MCP can be specified with the environment variableCYNOVELA_MCP_PYTHON. If it is not specified, the currently running Python is used as it is (routers/mcp.py).

How answers are built

  • Structured answers cannot be returned. Answers are free-form (Markdown as needed). Responses in JSON or with fixed tags are not provided. Citation of sources (in the form[1][2]) is implemented.
  • There is no automatic switching when confidence is low.cynovela.yaml hasconfidence_threshold (default0.4), but behavior that automatically switches to a general-knowledge mode when it falls below is not built in.
  • Self-evaluation of answers uses simple rules.evaluate_answer_quality() inadaptive_rag.py decides sufficiency by "the answer is empty," "fewer than 60 characters and few hits," and "contains a negative phrasing." It does not have the LLM do the evaluation.

このツールにできないこと 1. マスキングでできないこと (1/7)

この節がいちばん重い節です。 マスキングは「個人情報を隠す仕組み」ですが、隠せる範囲にははっきりした限界があります。マスキングが当たったからといって、資料の中の個人情報がすべて消えたわけではありません。 隠しきれないものが必ず残ります。

1.1 決まった形をした 13 種類しか、規則では取れない

guardrail.py のPII_PATTERNS に書かれている種別は、次の 13 種類だけです。

種別何を指すか種別何を指すか
URLhttp / https で始まるアドレスPASSWORD「パスワード: ○○」のようなラベル付きの値
EMAIL電子メールアドレスAPIKEYAPI キー・アクセストークン
PHONE_JP携帯電話番号（070 / 080 / 090）PRIVATEKEY秘密鍵のブロック
PHONE_LAND固定電話番号SSN米国の社会保障番号（3-2-4 の形）
CREDITクレジットカード番号IBAN国際銀行口座番号
MYNUMBERマイナンバー（個人番号）PASSPORT旅券番号（英字 2 + 数字 7）
IPV4IPv4 アドレス

これ以外のものは、規則では 1 件もマスキングされません。たとえば社員番号・顧客番号・契約番号・口座番号（IBAN 以外）・車両番号・保険証番号などは、対象外です。

規則は「形」で当てています。形が崩れていれば当たりません。逆に、形が偶然一致した無関係な数字はマスキングされます。

このツールにできないこと 1.2 / 1.3 氏名・住所・組織名・地名 (2/7)

1.2 氏名と住所は言語解析まかせ。lite にすると一切マスキングされない

氏名と住所は、上の 13 種類には入っていません。形が決まっていないので規則では取れず、言語解析（NER）の側で扱っています。

  • 設定はcynovela.yaml のpii_mode です。既定はstandard です。
  • standard のときだけ、PERSON_JP（氏名）とADDRESS_JP（住所）が働きます。
  • pii_mode をlite にすると、氏名も住所も一切マスキングされません。lite は正規表現だけで判定する道へ切り替わり、氏名・住所の認識器はそもそも組み立てられません（utils/metadata/pii.py のget_active_recognizers() とdetect_pii()）。

氏名の判定は、姓名として登録のある語しか当たりません。珍しい姓名、外国人名のカタカナ表記、あだ名、役職と一体になった書き方などは取りこぼします。住所も、都道府県から始まる書き方と郵便番号の形しか見ておらず、「本社ビル 3 階」「◯◯支店」のような書き方は住所として扱いません。

1.3 組織名と地名は、名前だけあって中身がない

get_active_recognizers() はORG_JP（組織名）とLOC_JP（地名）も返します。名前は返りますが、それを供給する認識器は 1 つも登録されていません（ツリー全体で、この 2 つの語はこの 1 行にしか出てきません）。

つまり組織名も地名もマスキングされません。 一覧に名前があるからといって、働いていると思わないでください。

このツールにできないこと 1.4 / 1.5 退行と、値が切れる条件 (3/7)

1.4 言語モデルが入っていないと、standard でも規則だけに退行する

氏名・住所の判定には spaCy / GiNZA の言語モデルが要ります。これが入っていない環境では、pii_mode がstandard のままでも、判定は正規表現だけに退行します。起動時にlaunch.sh が存在を確かめ、無ければ次の警告を出します。

⚠️  spaCy モデル '...' が未導入です (standard PII が regex フォールバックします)。'pip install -r requirements.txt' を実行してください。

この警告が出ているときは、氏名も住所もマスキングされていません。 起動は止まらないので、警告を読み飛ばすと、マスキングが効いているつもりのまま使ってしまいます。

1.5 パスワードと API キーは、空白・日本語・改行で切れる

PASSWORD とAPIKEY の規則は、値の部分を ASCII の図形文字だけで拾います（guardrail.py に「値は ASCII 図形文字[!-~] のみ（空白・CJK で必ず切れる）」と明記してあります）。このため、次のものは取れません。

  • 値の途中に空白が入っているもの（パスワード: abc def）→abc までで切れます
  • 値の途中に日本語が入っているもの
  • 改行をまたぐ値（ラベルと値の間の空白はタブと空白だけに限られ、改行はまたぎません）

また、ラベルと値の間に区切り（:：=＝ または「は」）が無いものは対象外です。password protection のような一般的な語を巻き込まないための設計で、その代償として「パスワード　abcdefgh」のような空白区切りは取れません。

このツールにできないこと 1.6 PDF の空白がマスキングを逃れる (4/7)

PDF は文字の並びではなく、文字を置く位置の情報として組まれています。そこから文字を取り出すとき、元の見た目には無かった空白が語の途中に入ることがあります。

マスキングの規則は文字の並びを見ているので、空白が 1 個入るだけで当たらなくなります。電子メールアドレスの場合、次のようになります。

取り出された文字列結果
taro.yamada@example.co.jpマスキングされる
taro.yamada @example.co.jpマスキングされない（@ の前で切れる）
taro.yamada@ example.co.jpマスキングされない（@ の後ろで切れる）

横断検索

MCP のツールにはsearch_across_collections（複数のコレクションをまたぐ検索）がありますが、画面（GUI）には横断検索の入口がありません。 画面からはワークスペースを 1 つ選んで検索します。

MCP

  • mcp_server.py は 11 個のツールを提供します。
  • MCP サーバーは、内部で Cynovela の REST API に認証付きで問い合わせる作りです。つまり本体が動いていないと MCP も動きません。
  • MCP を動かす Python の実行ファイルは、環境変数CYNOVELA_MCP_PYTHON で指定できます。指定が無ければ、いま動いている Python をそのまま使います（routers/mcp.py）。

回答の作り

  • 構造化された回答は返せません。 回答は自由形式（必要に応じて Markdown）です。JSON や決まったタグでの応答は用意していません。出典の引用（[1][2] の形）は実装済みです。
  • 信頼度の低いときの自動切り替えはありません。cynovela.yaml にconfidence_threshold（既定0.4）がありますが、下回ったときに一般知識モードへ自動で切り替えるような動きは組み込まれていません。
  • 回答の自己評価は単純な規則です。adaptive_rag.py のevaluate_answer_quality() は「回答が空」「60 文字未満でヒットも少ない」「否定的な言い回しを含む」で足りているかを決めます。LLM に評価させてはいません。

通行証（ログイン用のトークン）

通行証はPOST /api/auth/login が発行する JWT です。署名鍵は配布物には入っていません。受け取った側で初回起動時に暗号乱数から自動生成し、store/db/jwt/secret.key に保存します（config.py の_load_or_create_jwt_signing_key）。配布物を作るときに、この鍵は必ず落とします（共有すると、よそで発行された通行証が通ってしまうためです）。鍵の保存に失敗した場合は、その起動のあいだだけ有効な鍵になります（再起動すると発行済みの通行証は無効になり、再ログインで通ります）。
