Centered on FastAPI, this architecture combines the Provider abstraction (LLM / Embedding / Reranker / VectorStore / Classifier) with the Guardrail, RAG, and audit layers.

Decision logic: The critical components (FastAPI Server / Guardrail) are highlighted in the warning color. Provider wiring is done by_wire_providers_for_mode() in the priority orderyaml.reranker.provider then legacy (--mock has been removed).

RAG Pipeline Flow / RAG パイプラインフロー

This visualizes the seven stages from receiving the query to returning the answer. Hybrid fusion merges the rankings with RRF (k=60).
クエリ受信から回答返却までの 7 段階を可視化します。Hybrid 統合は RRF（k=60）で順位融合します。

Note: When Adaptive RAG (complexity score ≥ 2.0) starts, it enters an Agentic loop and performs up to three iterative searches using CRAG / Multi-Query / HyDE. The abstention decision uses the Vector cosine score (threshold 0.50) rather than RRF.
補足: Adaptive RAG（complexity score ≥ 2.0）が起動すると Agentic ループに入り、CRAG / Multi-Query / HyDE を活用して最大 3 回の反復検索が行われます。Abstention 判定は RRF ではなく Vector cosine スコア（しきい値 0.50）で行います。
known limitations: The structured answer template is not implemented, and free-form answers are the standard. The low-confidence fallback (threshold=0.50) is configured, but automatic switching when a search returns zero hits is not fully integrated.
既知の制限: 構造化回答テンプレートは未実装で、自由形式回答が標準です。低信頼度フォールバック（threshold=0.50）は設定済みですが、検索 0 件時の自動切替は完全には統合されていません。

Dual-Tier Storage Design / Dual-Tier 保管設計

The same document is stored separately in two lines: "raw" (original text, Fernet-encrypted) and "masked". At publish time,_mtws_publish =guardrail.mask_text_with_spans generates both tiers.
同じ文書を「raw（生本文・Fernet 暗号化）」と「masked（マスク済）」の 2 系統に分離して保管します。Publish 時に_mtws_publish =guardrail.mask_text_with_spans が両 tier を生成します。

Decision logic:tier_for_role(role) returns'raw' whenrole == 'admin' and'masked' otherwise, routing to the corresponding vault.vault_enc.enc_raw /dec_raw provide an idempotent interface using theenc: prefix.
判定ロジック:tier_for_role(role) がrole == 'admin' なら'raw' を、それ以外なら'masked' を返し、対応する保管庫へルーティングします。vault_enc.enc_raw /dec_raw がenc: プレフィックス付きの冪等なインターフェースを提供します。

Three-Layer Prompt Injection Defense / プロンプトインジェクション 3 層防御

The three-layer pipeline inrouters/chat.py inspects the input, retrieval, and output stages. On detection,PROMPT_INJECTION_BLOCKED is recorded inaudit_logs.
routers/chat.py の 3 層パイプラインで、入力・取得・出力の各段階を検査します。検出時はaudit_logs にPROMPT_INJECTION_BLOCKED を記録します。

Layer / 層Function / 関数Behavior / 動作
Input inspection / 入力検査 detect_prompt_injection Detects 14 English and Japanese patterns → blocks with HTTP 400
14 種の英日パターンを検出 → HTTP 400 で遮断
Post-retrieval inspection / Retrieval 後検査 filter_poisoned_chunks Excludes the matching chunks before the context is built
context 構築前に該当チャンクを除外
Output inspection / 出力検査 detect_output_exfiltration DetectsHACKED /PWNED /SECRET-ALPHA-TOKEN /[SYSTEM OVERRIDE] in the LLM response
LLM 応答中のHACKED /PWNED /SECRET-ALPHA-TOKEN /[SYSTEM OVERRIDE] を検知
known limitations: Complete detection of indirect prompt injection (instructions planted inside ingested documents) is planned for Phase 3. At present it relies on the pattern matching infilter_poisoned_chunks.
既知の制限: 間接プロンプトインジェクション（取り込んだ文書内に仕込まれた指示）の完全検出は Phase 3 で対応予定です。現状はfilter_poisoned_chunks のパターンマッチに依存しています。
