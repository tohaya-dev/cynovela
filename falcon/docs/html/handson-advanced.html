About this document
Cynovela is a completely unofficial learning tool, built so that an individual can understand the concepts of AI infrastructure tools by working with them hands-on. It is not a commercial product or an official implementation. Everything is implemented from scratch, on an OSS stack of FastAPI / SQLite / ChromaDB / BGE-M3 / a local LLM. It does not represent the official view of any company or product.

This hands-on covers workspace isolation, the difference in what each role sees, switching the startup mode, LAN sharing, and MCP (Model Context Protocol: the protocol for calling Cynovela from an external AI assistant) connection.

Hands-on (Advanced) 1. Demo of workspace isolation

Purpose

A workspace is the boundary of an information domain. You experience the behavior that, even for the same user, the visible collections change when the workspace they belong to is different.

Related schema

  • workspaces: the workspace itself
  • workspace_users: the membership relation between a workspace and a user
  • workspace_policies: the link between a workspace and a guardrail policy
  • workspace_sources: the link between a workspace and a data source
  • collections: the collections under a workspace (related throughworkspace_id)

Hands-on (Advanced) 2. The difference between what admin and viewer see

Purpose

You check the behavior that combines role-based access control (RBAC) with Tier1/Tier2 masking.

Summary of role permissions

RoleMain permissions
adminAll administrative functions. User management, viewing the PII detection history, searching the raw vault, no masking at the exit
viewerViewing only. RAG search and report viewing, searching the masked vault, masking at the exit
Names such ascurator /data-scientist are normalized toviewer and have no permissions of their own (the effective role is one of the 2 valuesadmin /viewer).

Hands-on (Advanced) 2. Decision logic and hands-on steps (2/2)

Internal decision logic (outline)

  • The vault to search is decided bytier_for_role(role) (admin → raw / others → masked)
  • The LLM output has masking applied according to the role by_mask_for_viewer()
  • Some endpoints (PII detection history, audit logs, user management, etc.) are guarded by_require_admin, so anyone other than admin cannot call them at all

Hands-on steps

  1. Prepare a collection that has published a file containing PII
  2. Log in asadmin and ask RAG Chat "tell me the contact details" → the raw body is displayed
  3. Ask the same question asviewer → it is replaced with something like[MASKED:EMAIL]
  4. Try to access the audit log screen asviewer → 403 Forbidden

Hands-on (Advanced) 4. Starting with LAN sharing

Purpose

You make the Cynovela running on your own PC reachable from another PC or a tablet on the same LAN.

Default restrictions

  • Bind address:127.0.0.1 (loopback only)
  • An IP allowlist middleware is in place, rejecting anything other than127.0.0.1 /localhost

Publishing to the LAN

Adding the--lan flag makes the bind0.0.0.0.

python server.py --demo --lan

To allow custom subnets, you can specify--allow-subnet multiple times.

python server.py --demo --lan --allow-subnet 192.168.1.0/24 --allow-subnet 10.0.0.0/8

ハンズオン（応用編） 1. デモシードと体験手順 (2/2)

ポリシーとワークスペースの組み合わせ例

ハンズオン（応用編） 2. admin / viewer の見え方の違い

目的

ロールベースアクセス制御（RBAC：Role-Based Access Control）と Tier1/Tier2 マスキングを組み合わせた振る舞いを確認します。

ロールの権限まとめ

ロール主な権限
admin全管理機能。ユーザー管理・PII 検出履歴閲覧・raw 保管庫検索・出口マスクなし
viewer閲覧のみ。RAG 検索とレポート閲覧・masked 保管庫検索・出口マスクあり
curator /data-scientist 等の名称はviewer に正規化され、固有権限はありません（実効ロールはadmin /viewer の 2 値）。

ハンズオン（応用編） 2. 判定ロジックと体験手順 (2/2)

内部の判定ロジック（概略）

  • 検索対象の保管庫はtier_for_role(role) で決定（admin → raw / その他 → masked）
  • LLM の出力は_mask_for_viewer() でロールに応じてマスク適用
  • 一部のエンドポイント（PII 検出履歴、監査ログ、ユーザー管理など）には_require_admin が掛かっており、admin 以外はそもそも呼べません

体験手順

  1. 同じ PII 入りファイルを Publish 済みのコレクションを用意
  2. admin でログインして RAG Chat に「連絡先を教えて」と質問 → 生本文が表示される
  3. viewer で同じ質問 →[MASKED:EMAIL] などに置換される
  4. viewer で監査ログ画面にアクセスを試みる → 403 Forbidden

ハンズオン（応用編） 4. LAN 共有起動

目的

自分の PC で動かしている Cynovela を、同じ LAN 上の別 PC やタブレットから触れるようにします。

既定の制限

  • バインドアドレス:127.0.0.1（loopback のみ）
  • IP アローリストミドルウェアが入り、127.0.0.1 /localhost 以外を拒否

LAN 公開

--lan フラグを付けるとバインドが0.0.0.0 になります。

python server.py --demo --lan

カスタムサブネットを許可する場合は--allow-subnet で複数指定できます。

python server.py --demo --lan --allow-subnet 192.168.1.0/24 --allow-subnet 10.0.0.0/8
