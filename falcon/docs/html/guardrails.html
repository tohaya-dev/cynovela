guardrails 1. How the Guardrails Work

The guardrail (a mechanism that detects and stops inappropriate input and output on the LLM path) works in Cynovela for the following three purposes.

  1. Ingest phase: at publish time, the PII (personal information) contained in the body text of each chunk is detected, and according to the policy one of "mask it", "exclude it from the vector DB", "only leave a log", or "let it through" is selected.
  2. Query acceptance phase: if there is a sign of prompt injection in the query of the user, it is blocked immediately with 400.
  3. Answer generation phase: the response text of the LLM is inspected for wording that carries confidential information out, and it is recorded on detection.

Removed (2026-07-24): the former "ingest without masking" (Raw mode,collections.raw_only) has been removed. Ingest always goes through masking, and search always reads the masked layer. The column is kept for the preservation of past data.

guardrails 6. Placement of the System Prompt

As an important principle of the design,the system prompt (the operating instructions given to the LLM in advance) is placed "after" the retrieved content (the body text of the retrieved documents).

If it were placed in front, a path would be created in which it can be overwritten by wording such as[SYSTEM OVERRIDE] written inside the body text of a document.

Principle: place the system prompt "after" retrieved_content. If it is placed in front, it becomes overwritable by a document.

guardrails 1. ガードレールの仕組み

ガードレール（guardrail：LLM 経路で不適切な入力・出力を検出して止める仕組み）は、Cynovela において次の 3 つの目的で機能します。

  1. 取込フェーズ: Publish のときに各 chunk の本文に含まれる PII（個人情報）を検出し、ポリシーに応じて「マスクする」「ベクター DB から除外する」「ログだけ残す」「通す」のいずれかを選びます。
  2. クエリ受付フェーズ: ユーザのクエリにプロンプトインジェクションの兆候があれば即座に 400 で遮断します。
  3. 回答生成フェーズ: LLM の応答テキストから機密情報持ち出し文言を検査し、検出時には記録します。

廃止（2026-07-24）: かつて存在した「マスキングなしで取り込む（Raw モード・collections.raw_only）」は廃止されました。取り込みは常にマスキングを経由し、検索は常にマスキング済みの層を引きます。過去データの列は保全のため残っています。

guardrails 6. システムプロンプトの配置

設計上の重要原則として、システムプロンプト（事前指定された LLM の動作指示）は retrieved content（取得した文書本文）の「後」に配置します。

前に置くとドキュメント本文の中に書かれた[SYSTEM OVERRIDE] などの文言で上書きされる経路ができてしまうためです。

原則: システムプロンプトは retrieved_content の「後」に配置すること。前に置くと文書で上書き可能になる。
