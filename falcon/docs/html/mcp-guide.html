About This Document
Cynovela is a completely unofficial learning tool, built by an individual to understand the concepts behind AI platform tools by hands-on work. It is not a commercial product nor an official implementation. Everything is originally implemented, on an OSS stack of FastAPI / SQLite / ChromaDB / BGE-M3 / a local LLM. It does not represent the official position of any company or product.

Cynovela can expose its own functions to external LLM clients as an MCP server of MCP (Model Context Protocol, an AI tool integration protocol proposed by the referenced AI tool). This document explains the concept of MCP, the MCP tools that Cynovela exposes, and the connection procedure.

MCP Integration Guide 1. What MCP Is

MCP is a standard protocol by which an AI assistant (a client) calls the functions (tools) of an external system.

  • Client: the side the user talks to, such as LM Studio or a supported LLM client
  • Server: the side that provides the functions (this is where Cynovela belongs)
  • Tool: an operation exposed by the server (search, registration, reference, and so on)

With MCP, when the user says to an LLM client "search our internal documents", the LLM calls the search tool of Cynovela and generates an answer based on the results; that is the integration that is established.

MCP Integration Guide 3-2. Configuration Example

Register the following in the MCP server settings of LM Studio. For the actual key names, refer to the documentation of the client.

{
  "mcpServers": {
    "cynovela": {
      "command": "/path/to/python",
      "args": [
        "/Users/<ユーザー名>/Projects/cynovela/cynovela/mcp_server.py"
      ],
      "env": {
        "CYNOVELA_BASE_URL": "http://127.0.0.1:8765",
        "CYNOVELA_TOKEN": "<認証トークン>"
      }
    }
  }
}

MCP Integration Guide 4. Limitations Specific to the conda Environment

Cynovela is built on the premise that it runs in a conda environment (cynovela). When calling the API of the main body from the MCP server, the path of the Python executable must be stated explicitly.

4-1. Specifying the Python path

The absolute path of the Python used to run the MCP script can be specified with the environment variableCYNOVELA_MCP_PYTHON.

export CYNOVELA_MCP_PYTHON=~/miniforge3/envs/cynovela/bin/python

Without this specification, the conda environment is not activated in the child process started by a client such as LM Studio, and an ImportError of a dependency library may occur.

MCP Integration Guide 5. Notes on Authentication

5-1. Bearer token

The MCP server authenticates to the API of the Cynovela main body with theAuthorization: Bearer <token> header. The token is passed by an environment variable on the client side.

  • Authentication uses the JWT issued byPOST /api/auth/login. The oldBearer demo-token-<user_id> form has been removed and is not accepted.
  • For production operation, the introduction of JWT authentication is required (not implemented at this point).

5-2. Role permissions

Calls through MCP also pass the same role (admin / curator / viewer) permission checks as the API of the main body. In particular, administration tools such ascreate_workspace andpublish_collection may require admin permission.

5-3. Audit log

Operations through MCP are also recorded in the same audit log (theaudit_logs table) as the main body. The history can be confirmed withget_audit_logs.

MCP 連携ガイド 1. MCP とは

MCP は、AI アシスタント（クライアント）が外部システムの機能（ツール）を呼び出すための標準プロトコルです。

  • クライアント: LM Studio や対応する LLM クライアントなど、ユーザーが対話する側
  • サーバー: 機能を提供する側（Cynovela がここに該当）
  • ツール: サーバーが公開する操作（検索、登録、参照など）

MCP を使うと、ユーザーが LLM クライアントに「うちの社内文書を検索して」と話しかけたときに、LLM が Cynovela の検索ツールを呼び出し、結果を踏まえて回答を生成する、という連携が成立します。

MCP 連携ガイド 4. conda 環境固有の制限

Cynovela は conda 環境（cynovela）で動作する前提で構築されています。MCP サーバーから本体 API を呼び出す際は、Python 実行ファイルパスを明示する必要があります。

4-1. Python パスの指定

環境変数CYNOVELA_MCP_PYTHON で MCP スクリプト実行用 Python の絶対パスを指定できます。

export CYNOVELA_MCP_PYTHON=~/miniforge3/envs/cynovela/bin/python

この指定がない場合、LM Studio などのクライアントが起動した子プロセスでは conda 環境がアクティブにならず、依存ライブラリの ImportError が発生する可能性があります。

MCP 連携ガイド 5. 認証の注意

5-1. ベアラートークン

MCP サーバーは Cynovela 本体 API に対してAuthorization: Bearer <token> ヘッダーで認証します。トークンはクライアント側の環境変数で渡します。

  • 認証はPOST /api/auth/login が発行する JWT です。旧Bearer demo-token-<user_id> 形式は廃止済みで受理しません。
  • 本番運用では JWT 認証導入が必要です（現時点では未実装）。

5-2. ロール権限

MCP 経由の呼び出しも本体 API と同じロール（admin / curator / viewer）の権限チェックを通過します。特にcreate_workspace やpublish_collection などの管理系ツールは admin 権限を要する場合があります。

5-3. 監査ログ

MCP 経由の操作も本体と同じ監査ログ（audit_logs テーブル）に記録されます。get_audit_logs で履歴を確認できます。
