このドキュメントについて
Cynovelaは、AI基盤ツールのコンセプトを個人が手を動かして理解するために作った完全非公式の学習ツールです。商用製品・公式実装ではありません。実装はすべてオリジナルで、FastAPI / SQLite / ChromaDB / BGE-M3 / ローカルLLM という OSS スタックで構成されています。会社・製品の公式見解を一切代表しません。

このドキュメントでは、Cynovela を初めて起動し、最初の RAG（Retrieval-Augmented Generation：検索拡張生成）質問を投げるまでの最短手順を示します。

Cynovela はローカル PC 上で動作します。以下が事前に整っている必要があります。

項目内容
Pythonconda（Anaconda / Miniforge）環境を利用します
ローカル LLMLM Studio もしくは OpenAI 互換 API を提供するローカルサービス
推奨 RAM起動モード（--mode）に応じて 4GB〜128GB
ネットワーク初回起動時のモデルダウンロードに必要

質問への答えを作るには実 LLM が要ります。以前あった --mock（モック LLM）は撤去済みで、いま指定するとエラーで止まります。

クイックスタート 2. conda 環境のセットアップ

Cynovela は conda 環境上で動作確認しています。以下の手順で環境を作成してください。

# conda 環境を作成（任意の名前。例: cynovela）
conda create -n cynovela python=3.11 -y

# 依存ライブラリをインストール

Cynovela は起動時に「Preflight チェック」というモデル存在確認を行います。起動モード（--mode）に応じて必要な Embedding（埋め込み：テキストをベクトル化するモデル）が異なります。

lite切替は未配線＝実際は BAAI/bge-m3（動作は text と同じ・表示名が変わるだけです）—
lite-en切替は未配線＝実際は BAAI/bge-m3（動作は text と同じ・表示名が変わるだけです）—

クイックスタート 4. 起動コマンド（実 LLM 利用時） (2/2)

実 LLM を使う場合は、LM Studio を http://localhost:1234 で立ち上げてから次のコマンドを実行します。

python server.py --demo

LM Studio が別ポートやリモートにある場合は次のように指定します。

python server.py --demo --lmstudio-url http://localhost:1234

起動に成功すると、デフォルトでは http://127.0.0.1:8765 で GUI と API が公開されます。

クイックスタート 5. デモアカウントでログイン

ブラウザで http://127.0.0.1:8765 を開きます。--demo で起動した場合、デモ用のユーザーが自動投入されています。

DB が保持するロールは admin / viewer の 2 値です。

ロール権限
admin全機能。ユーザー管理・システム設定・PII 検出履歴の閲覧などフル権限
viewer閲覧のみ。RAG 検索・レポート閲覧
curator / data-scientist 等の名称は内部的に viewer へ正規化されます。

出荷 demo.db の実ログイン情報:

ユーザー名ロールパスワード
cynovelaadmin初回ログイン時に変更を強制（固定 PW は配布しません）
demoviewer同梱の資格情報ファイル（配布物の tar とは別便で受け取る *.admin-password.txt）の viewer_password を参照。固定 PW は配布しません

ログイン後、ロールに応じて表示される画面と操作可能な範囲が変わります。

クイックスタート 6. 最初のワークスペース作成

「ワークスペース（Workspace）」は、ユーザー・ポリシー・コレクションをまとめる管理単位です。--demo 起動では、同梱のダミー資料が入ったワークスペースが 1 件だけ入っています（空のシード WS 3 件は 2026-07-30 に撤去済みで、起動時に取り除かれます）。ガードレールポリシー 3 件はシードされるので、作成したワークスペースに割り当てて使います。

新規ワークスペースを作る場合は、GUI の「ワークスペース管理」画面から作成できます。後述の「ハンズオン（基礎編）」で詳しい手順を示します。

クイックスタート 7. 最初のファイル取り込み

ワークスペースの下に「コレクション（Collection）」を作り、そこに対象ファイルを取り込みます。コレクションはファイル群とチャンク（分割）戦略の単位で、draft → ingested → ready という状態遷移を持ちます。

GUI 上では以下の順で操作します。

  1. ワークスペースを選択
  2. 「コレクション作成」ボタンを押し、名前と RAG 戦略（simple / hybrid_bm25 / contextual）を指定
  3. ファイルをアップロード（ドラッグ＆ドロップ可）
  4. 「Publish（公開）」を実行し、ready 状態にする

クイックスタート 7. Publish で行われる処理 (2/2)

Publish の過程で以下が行われます。

  • テキスト抽出（PDF / DOCX / 画像 OCR ほか）
  • チャンク分割（既定 500 文字、オーバーラップ 50 文字）
  • PII 検出とマスキング（取込時マスキング）
  • Embedding 生成と ChromaDB への保存
  • BM25 インデックス構築
補足: Publish はバックグラウンドで動き、SSE（Server-Sent Events）で進捗を返します。完了時には publish_history テーブルに件数や所要時間が記録されます。

クイックスタート 8. 最初の質問

ready 状態のコレクションに対して、GUI 上の「RAG Chat」画面から質問を投げます。

たとえば次のように尋ねます。

このドキュメントで扱われている主なトピックは何ですか？

回答とともに、出典として [1][2] のような引用番号付きでチャンクが表示されます（config.rag.citation_enabled = true の場合）。

ロールによる違いも体験できます。

  • admin ログイン時: 生本文（raw）保管庫を検索。出力にもマスクは入りません。
  • viewer ログイン時: マスク済み本文（masked）保管庫を検索。LLM 出力にも出口マスクが適用され、PII（Personally Identifiable Information：個人情報）はマスキングに置換されます（curator / data-scientist 等は viewer に正規化）。
